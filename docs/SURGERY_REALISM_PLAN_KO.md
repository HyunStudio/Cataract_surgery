# 수술 사실성 확장 — 추가 기획 및 설계 (v1.3)

작성: 2026-10-13 | 상태: 구현 완료 · 테스트 통과 | 관련: [제품 기획서](PRODUCT_SPEC_KO.md), [안전 원칙](SAFETY.md)

플레이어는 **집도의**다. 실제 백내장 수술(초음파 유화술)의 **순서·판단·합병증 상황**을 최대한 사실적으로 재현한다. 수술 시작부터 성공·실패 판정까지 한 흐름으로 진행된다.

## 1. 범위 원칙

"실제 수술과 동일"을 목표로 하되, [SAFETY.md](SAFETY.md)의 경계는 유지한다.

| 사실적으로 구현하는 것 | 구현하지 않는 것 (안전 원칙) |
|---|---|
| 실제 수술 단계 순서와 각 단계의 필수 처치 (점탄물질 주입, 수력분리 등) | 초음파 출력·흡인 압력·유량 등 장비 설정값 |
| 단계별로 실제 발생하는 합병증과 집도의가 보게 되는 징후 | 약물명·용량, 실제 절개 치수 |
| 합병증 인지 → 판단(계속/관리·도움 요청/안전 중단) → 결과 | 합병증 처치의 세부 조작 절차 (구조 알고리즘) |
| 위험 요인이 있는 증례 브리핑 (예: 산동 불량 위험 약물 복용력, 거짓박리증후군) | 실제 환자 데이터, 임상 결과·시력 예측 |
| 성공 / 합병증 관리 / 합병증 동반 완료 / 안전 중단 / 중대 실패 판정 | 술기 자격 평가, 검증된 임상 점수 |

"관리" 선택지는 **"중단·안정화·상급자/망막팀 요청"** 수준으로 추상화한다. 어떤 기구로 어떻게 처치하는지는 알려 주지 않는다.

## 2. 실제 수술 흐름과 게임 단계 대응

| 게임 단계 | 실제 수술 단계 | 집도의 조작 | 필수/권장 처치 |
|---|---|---|---|
| PREOP | 수술 전 타임아웃 (환자·수술 눈·IOL 확인) | Space: 타임아웃 시행 | 불일치 발견 시 반드시 중단 |
| ANESTHESIA | 점안 마취, 소독, 드레이핑, 개검기 | Space | — |
| ENTRY | 주절개 + 보조절개 2곳, 점탄물질(OVD) 주입 | 표적 클릭 3회, **V** | OVD 미주입 시 전방이 얕아짐 |
| CAPSULE | 연속곡선 전낭절개(CCC) | 링 따라 드래그 | 링 밖으로 벗어나면 전낭 방사상 파열 |
| PHACO | 수력분리 → 핵 유화·흡인 | **D** 후 중앙에서 누르고 유지 | 수력분리 생략 시 소대·낭 스트레스 증가 |
| CORTEX | 관류·흡인(I/A)으로 피질 제거 | 중앙에서 누르고 유지 | 주변부 과흡인 → 후낭 스트레스 |
| IOL | 낭 내 OVD 주입 → IOL 삽입·중심 맞춤 | **V** 후 중심 클릭 | OVD 없이 삽입 시 감점 |
| CLOSE | IOL 위치, 절개창 밀폐 확인, 인계 | 체크 3개 | 누출 발견 시 밀폐 후 재확인 |
| RECOVERY / ABORTED / FAILED | 결과 판정·디브리핑 | — | — |

## 3. 증례(시나리오)와 위험 요인 브리핑

PREOP 화면에서 **증례 브리핑**(합성 환자 정보와 위험 요인)을 먼저 보여 준다. 실제 집도의가 수술 전에 위험을 예측하는 과정과 같다.

| 키 | 증례 | 브리핑에 나오는 위험 요인 | 발생 상황 |
|---|---|---|---|
| 1 | normal | 특이사항 없음 | 합병증 없음 (모범 수술) |
| 2 | motion | 불안, 폐소공포 | 전낭절개 중 환자 움직임 |
| 3 | vitals | 만성 폐질환 | 유화술 진입 시 산소포화도 저하 |
| 4 | capsule | 후극 백내장 (후낭 취약) | 유화술 진입 시 후낭 파열 |
| 5 | timeout | 동의서 확인 필요 | 타임아웃에서 수술 눈 표시 불일치 |
| 6 | iris | 알파차단제 복용력 (홍채 이완 위험) | 유화술 중 홍채 탈출 |
| 7 | zonules | 거짓박리증후군 | 전낭절개 중 소대 약화 징후 |
| 8 | leak | 특이사항 없음 | 마무리 점검에서 절개창 누출 |
| 9 | random | 정보 부족: 경계 유지 | 시드에 따라 합병증 2개 무작위 |

## 4. 합병증 카탈로그 (징후 → 판단 → 결과)

모든 합병증은 **안전 정지(Safety hold)** 로 시작한다. 도구가 멈추고, **A(평가)** 를 눌러 징후를 확인해야 판단할 수 있다. 판단이 필요한 합병증은 평가 후 선택지가 나온다.

- **1 계속 진행**: 문제를 무시하고 원래대로 진행
- **2 관리**: 중단·안정화·도움 요청 후 수정된 계획으로 진행
- **3 안전 중단**: 수술을 멈추고 의뢰·연기

| 합병증 | 단계 | 집도의가 보는 징후 | 1 계속 | 2 관리 | 3 중단 |
|---|---|---|---|---|---|
| 수술 부위 불일치 (중대) | PREOP | 동의서는 좌안, 표시는 우안 | **중대 실패** (잘못된 부위 수술) | 재확인·표시 수정 후 진행 | 안전 중단 (수술 연기) |
| 환자 움직임 | CAPSULE | 현미경 시야 흔들림, 맥박 상승 | — (평가만으로 해소) | — | 가능 |
| 바이탈 경보 | PHACO | SpO2 저하, 빈맥 | — (마취팀 평가로 해소) | — | 가능 |
| 전낭 방사상 파열 | CAPSULE | 절개 가장자리가 주변부로 찢어져 나감 | 파열 진행 → 유화술 중 **후낭 파열** 유발 | 낭 보존 작업으로 계속 (스트레스 1.5배) | 안전 중단 |
| 소대 약화 | CAPSULE | 기구 따라 낭이 움직임, 수정체 흔들림 | 소대 해리 → 스트레스 2배, IOL 편위 | 낭 지지 후 조심스럽게 진행 (1.2배) | 안전 중단 |
| 홍채 탈출 | PHACO | 주절개로 홍채 탈출, 동공 축소 | 홍채 손상, 작업 영역 크게 축소 | 홍채 정복·동공 안정화 후 진행 (영역 약간 축소) | 안전 중단 |
| 후낭 파열 (중대) | PHACO/CORTEX | 전방 갑자기 깊어짐, 핵 조각이 뒤로 가라앉음 | **중대 실패** (핵 조각 유리체 낙하) | 중단·안정화·상급자 요청, 이후 스트레스 2배, IOL 섬모체고랑 고정 | 안전 중단 (망막팀 의뢰) |
| 절개창 누출 (중대) | CLOSE | 절개창에서 방수 누출, 전방 얕아짐 | **중대 실패** (누출 상태로 종료, 감염 위험) | 절개창 밀폐 후 재확인 | 안전 중단 |

후낭 파열은 증례 외에도 생길 수 있다. 조직 스트레스가 100%에 도달하거나 방사상 파열을 무시하면 발생한다. 관리한 뒤에도 다시 스트레스 100%에 도달하면 또 발생한다.

## 5. 결과 판정

| 결과 | 조건 | 표시 |
|---|---|---|
| **SUCCESS** | 합병증 없이 완료 | 성공 — 합병증 없는 수술 |
| **COMPLICATION MANAGED** | 합병증이 있었으나 모두 관리하고 완료 | 합병증 관리 후 완료 |
| **COMPLICATED** | 비중대 합병증을 무시한 채 완료 | 합병증 동반 완료 (개선 필요) |
| **SAFE ABORT** | 집도의가 안전 중단 | 안전 중단 (합병증 후 중단이면 올바른 판단) |
| **CRITICAL FAILURE** | 중대 합병증을 무시하고 계속 | 중대 실패, 점수 0 (안전 거부권) |

점수(100점)는 기존 구성을 유지한다. 술기 항목(14점)에서 다음을 감점한다: 스트레스 경고 4점, 전낭절개 전 OVD 누락 3점, 수력분리 누락 3점, IOL 전 OVD 누락 3점. 점수는 합성 게임 점수이며 임상 척도가 아니다.

## 6. 설계

### 6.1 모듈
- `ophthosim/complications.py` (신규): 합병증 카탈로그(`Complication`), 증례 브리핑(`CASES`), 무작위 풀, 결과 라벨. 데이터만 담고 상태를 바꾸지 않는다.
- `ophthosim/engine.py`: 단일 상태머신.
  - `Phase.FAILED` 추가
  - 행동 추가: `ovd`, `hydro`, `decide`(`continue`/`manage`/`refer`)
  - 상태 추가: `hazards`(예정 합병증), `fired`, `awaiting_decision`, `flags`(영구 사건 기록), `managed`, `ignored`, 작업 반경, 스트레스 배율
  - 함수 추가: `outcome()`, `checklist()`
- `ophthosim/replay.py`: 새 행동을 기록하도록 확장, 리플레이 스키마 v3.
- `app.py` / `gl_surgery.py`: 증례 브리핑, 단계 체크리스트, 합병증 카드(징후·선택지), 결과 화면, 키 V/D/1–3, 증례 1–9.
- `input3d.Surgery3DController.command`: 새 행동 허용.

### 6.2 상태 전이 규칙
1. 합병증 발화: 조건을 만족하고 다른 경보가 없을 때 발생한다. 경보가 있으면 다음 기회로 미룬다. 발생하면 `patient.alert`, `paused`, `alert` 이벤트를 남긴다.
2. `assess`: 판단이 필요 없는 경보는 해소한다(기존과 같음). 판단이 필요한 합병증은 `awaiting_decision`으로 바꾸고 정지 상태를 유지한다.
3. `decide`: `awaiting_decision`일 때만 받는다.
   - `continue`: 중대 합병증이면 FAILED. 비중대이면 악화 효과를 적용하고 `ignored`에 기록한다.
   - `manage`: 관리 효과를 적용하고 `managed`에 기록한다.
   - `refer`: 안전 중단한다.
4. `abort`는 언제든 가능하다(기존과 같음).
5. 영구 사건(`flags`)은 초기화하지 않는다.
6. 모든 무작위성은 시드 고정 RNG를 쓰고, 선택된 합병증은 `start` 이벤트에 기록한다.

### 6.3 호환성
- 기존 alert 키 `CAPSULE INTEGRITY`는 유지하고, 화면에는 "POSTERIOR CAPSULE RUPTURE"로 표시한다.
- 수술 완료 시 `ending` 문자열 `SIMULATION COMPLETE`는 유지하고, 결과는 `outcome()`으로 따로 판정한다.
- 이벤트 스키마 v3, 리플레이 스키마 v3. 이전 리플레이는 검증을 거부한다.

## 7. 테스트 계획
- 증례별 전체 흐름: 9개 증례의 모든 판단 분기에서 결과 판정이 맞는지 확인한다.
- 판단 규칙: 평가 전 판단 불가, 정지 중 수술 조작 불가, 중대 합병증 무시 시 FAILED와 점수 0.
- 처치 효과: OVD 유무에 따른 전낭절개 허용 범위, 수력분리 누락 시 스트레스, IOL 전 OVD, 누출 밀폐 후 재확인.
- 연쇄: 방사상 파열 무시 → 후낭 파열, 소대 해리 무시 → IOL 편위, 관리 후 스트레스 재도달 → 재발생.
- 재현성: 모든 분기를 리플레이로 재현해 스냅샷·이벤트가 같은지 확인한다. 무작위 증례는 시드별로 결정적이어야 한다.
- 비정상 입력: `decide`·`ovd`·`hydro`에 잘못된 값을 넣어도 퍼즈 테스트에서 예외가 나지 않아야 한다.
- 화면: 2D와 3D 모든 단계·합병증 카드·결과 화면 렌더링, 실제 GPU 스모크 테스트 통과, 스크린샷 육안 검수.

## 8. 구현 결과 (2026-10-13)

- 테스트 607개 통과. 이 중 55개는 `tests/test_surgery_realism.py`에 새로 추가했다: 9개 증례, 모든 판단 분기, 연쇄 합병증, 리플레이, 퍼즈, 2D·3D 화면.
- Windows RTX 3070 실제 GPU 스모크 6개 시나리오 통과: 정상 / 스트레스 경고 / 환자 움직임 / 후낭 파열 판단 / 홍채 탈출 관리 / 수술 부위 불일치 무시 → 중대 실패.
- 설계 대비 추가 변경:
  - 단계가 바뀌면 손에 쥔 도구 동작이 자동으로 해제된다(실제로 단계마다 기구를 바꾸는 것과 같음). 전낭절개를 끝낸 드래그가 그대로 핵 제거로 이어지던 문제를 막는다.
  - 3D 접촉 가이드도 엔진과 같은 규칙을 쓴다(얕은 전방에서 좁아지는 전낭절개 허용 범위, 홍채 문제로 줄어든 작업 반경).
- 한계:
  - 3D 렌더러에는 홍채 탈출·누출 같은 합병증의 시각 효과가 아직 없다(정보 카드로만 표시). 2D 화면에는 동공 축소, 전낭 파열선, 후낭 파열, 홍채 탈출, 누출 방울이 그려진다.
  - 합병증 발생률과 판단 결과는 임상적으로 검증되지 않았다. 의료 전문가 검토가 필요하다.

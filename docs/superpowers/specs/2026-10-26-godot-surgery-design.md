# 백내장 수술 시뮬레이터 — Godot 3D 전환 설계

작성: 2026-10-26. 상태: 사용자 “완성해” 요청으로 구현 승인. Godot 구현과 검증은 docs/GODOT_VALIDATION.md 참고.

## 의도와 결정의 출처

사용자는 저장소의 진행 상황과 기획을 이어 받아, 실제 수술 환경처럼 보이는 3D 공간에서 상황에 맞는 도구를 사용하여 수술 전 과정을 플레이하는 게임을 요청했다. 전용 3D 엔진으로의 전환은 사용자가 선택했다.

Godot 4 안정 버전, GDScript, Windows x64, 마우스·키보드, 한국어 기본 UI, 오프라인 싱글 플레이는 작성자의 제안이다. 정확한 엔진 버전은 구현 시작 시 공식 안정 배포를 확인하고 고정한다. 목표는 게임으로서의 시각적 설득력과 명확한 상호작용이다. 임상 훈련 효과나 실제 조직 역학을 입증하는 프로젝트로 해석하지 않는다.

## 현재 기반과 전환 방법

- 기존 Python·Pygame·ModernGL 코드는 유지한다. 2026-10-26 로컬 pytest 실행 결과 522개 통과. 이 결과는 새 Godot 구현의 검증을 대신하지 않는다.
- 기존 engine.py의 단계, 위험 이벤트, 경고 중 조작 차단, 결과 규칙을 GDScript로 이식한다. Python을 Godot 런타임에 연결하거나 매 프레임 IPC로 호출하지 않는다.
- 기존 결정적 리플레이는 참고 규격이다. 새 게임은 도구와 접촉 명령을 포함하는 독립적인 버전 2 세션 형식을 사용한다. 기존 버전 1 파일의 Godot 재생은 첫 출시 범위에 없다. Python 검증기는 유지한다.
- 새 프로젝트는 저장소의 godot/ 아래 둔다. 기존 Python 실행 경로와 기존 문서의 역사적 기록을 보존하고 README에 각 구현 상태를 구분한다.

## Approaches

1. 기존 Python·ModernGL 확장: 상태 엔진 재사용이 쉽지만 장면·에셋·애니메이션·에디터 제작 도구를 직접 보완해야 한다. 사용자 선택에서 제외됐다.
2. 전용 3D 엔진으로 전환: 사용자가 선택한 방향. 장면·재질·충돌·애니메이션을 엔진에서 관리하고 기존 게임 규칙을 이식한다.
3. 전용 엔진 선택은 Godot 4를 제안한다. Unity/Unreal로의 전환보다 이 저장소에 독립적인 소규모 프로젝트를 추가하는 구성을 우선한다. 타 엔진의 우열이나 사용자의 엔진 선호를 확정한 것으로 간주하지 않는다.

## 첫 완성 버전의 범위

한 사례를 선택해 준비부터 결과까지 완료할 수 있는 Windows 게임을 만든다. 정상, 환자 움직임, 모니터 이상, 수정체낭 손상의 네 사례를 제공한다. 튜토리얼과 표준 모드는 같은 규칙을 쓰고 가이드 표시 수준만 다르게 한다.

실사 사진 합성 대신 자체 제작한 입체 모델과 재질, 조명, 도구 동작으로 수술실과 현미경 시야를 구성한다. 방 전체 자유 이동보다 현미경 조작을 우선한다. VR·햅틱·멀티플레이·실제 약물/장비 설정·의학적 물성 기반 유한요소 해석은 첫 버전에 포함하지 않는다.

단순 도구 이름 변경, 단계마다 클릭 한 번으로 자동 성공, 3D 외형만 바뀌고 조직 상태와 무관한 연출은 완성으로 인정하지 않는다.

## 장면과 화면

- 사례 선택/브리핑: 가상 환자, 수술 부위 확인, 모드 선택, 조작 설명.
- 수술실 전체 보기: 수술대, 환자 머리와 드레이프, 개검기, 현미경 본체, 도구 트레이, 장비와 모니터. 준비 완료 후 현미경으로 전환한다. 전체 보기는 수술 중 관찰용으로도 접근 가능하지만 그동안 도구 작동을 중지한다.
- 현미경: 안구가 중앙, 도구와 현재 목표가 왼쪽, 합성 환자 모니터가 오른쪽, 깊이 단면과 단계 진행이 아래쪽. 경고가 작업 영역을 가리지 않는다.
- 결과: 완료/안전 중단 구분, 단계별 시간, 경로 오차, 불필요한 접촉, 도구 오류, 경고 반응, 최종 조직 상태와 점수 근거. JSONL 내보내기와 재시작.

주 수술 화면은 고정 현미경 카메라를 사용한다. 해부학 관찰 모드에서만 자유 회전을 허용하고 수술 입력은 잠근다. 회전 후 수술 복귀 시 표준 카메라와 새 입력을 요구한다. 1080p를 우선 검수하고 배율/창 크기에 따라 주변 패널을 접거나 스크롤한다.

## 3D 자산

안구는 공막·각막·홍채·수정체낭·혼탁 수정체·잔여 피질·IOL을 분리한다. 각막은 투명 재질과 반사 하이라이트, 홍채는 방사형 질감, 수정체는 영역별 혼탁/파편, IOL은 광학부와 지지부로 표현한다. 각막 투명도 때문에 클릭 대상이나 도구 팁이 잘못 선택되지 않도록 렌더 레이어와 접촉 레이어를 분리한다.

최초 자산은 자체 생성 메시와 자체 재질로 제작하고 런타임에 외부 다운로드하지 않는다. 완성 시 실루엣·팁이 구분되는 도구, 열린 전안부 구조, 수술대/드레이프/현미경/트레이를 실제 3D로 표시해야 한다. Blender 설치는 필수 조건이 아니다. 세부 조형을 교체할 때는 glTF/GLB를 사용한다. 자산 manifest에 제작 방식·라이선스·축·모델 단위·버전을 기록한다. 모델 단위는 게임 내부 값이며 실제 수술 길이로 표시하지 않는다.

## 도구와 조작

첫 버전 도구는 절개도, 전낭 집게, 수류분리용 캐뉼라, 초음파 유화 핸드피스, 관류/흡인 핸드피스, IOL 인젝터, 위치 조정 도구다. 각각 별도 실루엣과 팁 메시, 유효 단계, 접촉 대상, 클릭/유지/드래그 동작을 갖는다.

마우스 이동은 도구 팁의 평면 이동, 휠은 확대, Shift+휠은 깊이, 왼쪽 버튼은 도구 작동, 오른쪽 버튼은 작동 해제, 숫자키/트레이 클릭은 도구 선택이다. Esc는 일시정지, 별도 버튼/단축키로 안전 중단한다. 도구 교체는 기존 누름 상태를 해제하며 새 클릭 전 작동하지 않는다. UI 위, 화면 밖, 잘못된 깊이, 경고, 종료 상태에서 수술 명령을 생성하지 않는다. 시점 조작과 수술 작동을 동시에 허용하지 않는다.

잘못된 도구는 이유를 표시하고 진행을 차단한다. 올바른 도구라도 팁이 대상과 만나고 단계별 동작 조건이 충족되어야 진행한다. 커서만 목표에 올려 놓거나 버튼을 계속 누른 채 단계가 바뀌는 것으로 다음 단계를 자동 수행할 수 없다.

## 플레이 흐름과 조직 반응

| 단계 | 도구/행동 | 모델 상태와 완료 조건 |
|---|---|---|
| 준비 | 부위·사례 확인, 준비 체크 | 필수 확인과 안정 상태 후 현미경 진입 |
| 진입 | 절개도 접근/드래그 | 지정 게임 영역에서 경로·깊이 조건 충족, 절개 표시 생성 |
| 전낭 | 집게로 연속 경로 추적 | 순서 있는 폐곡선의 범위/폐쇄/오차 평가, 낭 개구부 메시 갱신 |
| 분리 | 캐뉼라로 지정 게임 영역 조작 | 분리 진행과 수정체 이동 가능 상태 표시 |
| 수정체 제거 | 유화 핸드피스 접촉/유지 | 접촉한 영역의 파편 생성·제거, 남은 혼탁이 영역별 감소 |
| 피질 정리 | 관류/흡인 도구 조작 | 팁 주변 잔여물만 감소, 잔여물 기준 충족 |
| IOL | 인젝터 삽입 후 위치 조정 도구 | 렌즈 전달·전개·중심 정렬을 각각 완료 |
| 마무리 | 최종 상태 확인 | 잔여물·정렬·조직 안정·인계 확인 후 회복 |
| 결과/중단 | 평가 또는 중단 사유 확인 | 사례 기록과 점수 근거 표시, 재시작/내보내기 |

절개·개구부는 제한된 작업 영역의 경로/마스크/미리 분할된 메시로 표현한다. 수정체는 유한한 영역과 파편으로 구성하고 흡인은 실제 팁의 근접 영역에만 적용한다. 무제한 실시간 메시 절단이나 실제 수술 물성은 구현하지 않는다. 분리 단계와 IOL 세부 상태는 기존 Python보다 확장된 상태이며 새 테스트로 검증한다.

## 상태·접촉·애니메이션 구조

ProcedureSession이 유일한 상태 변경 권한을 가진다. PatientState, EyeState, ToolState, 단계별 진행 데이터를 보유한다. InputRouter → ToolController → InteractionResolver → 의미 명령 → ProcedureSession → 읽기 전용 프레임 상태 → 3D 장면/HUD/오디오/SessionRecorder 흐름으로 분리한다.

렌더 메시와 단순화된 접촉 표면을 분리하되 동일한 변환을 사용한다. 카메라 레이로 작업 좌표를 얻고 도구 팁의 이전/현재 위치를 연결한 이동 구간과 대상 영역을 검사하여 빠른 이동 중 관통 누락을 막는다. 깊이·유효 도구·버튼 상태·단계·위험 잠금을 함께 검증한다. 조직 변경은 고정 60Hz 게임 틱의 의미 명령으로만 일어난다. 셰이더·입자·애니메이션은 게임 상태를 읽고 진행을 결정하지 않는다.

일시정지·경고는 게임 시간과 애니메이션을 함께 멈추며 해제 시 누적 시간과 누름 상태를 버린다. 환자 움직임은 게임 좌표 변환과 렌더 변환이 동일한 눈 루트에서 적용되고 경고 중 조작이 차단된다. 저움직임 설정은 화면 흔들림을 없애되 위험 상태와 잠금은 유지한다.

## 시나리오·평가·기록

네 사례는 고정 시드와 단계 진입 시 이벤트로 재현한다. 경고가 발생하면 수술 명령을 차단하고 평가/재개 가능 여부/안전 중단으로 분기한다. 낭 손상과 같은 회복 불가 사례는 무시하고 진행할 수 없다.

게임 평가는 단계 완료, 경로 품질, 접촉 오류, 잔여물, IOL 정렬, 경고 대응을 근거로 제공한다. 안전 중단은 완수와 다른 긍정적 결과로 표시한다. 세부 가중치는 구현자의 판단으로 문서화하고 임상 능력 척도로 표시하지 않는다.

버전 2 로그에는 engine_build, case, seed, simulation_tick, 도구 선택과 정규화된 의미 입력, 단계/경고/결과, 최종 상태 digest를 기록한다. 동일 엔진 빌드의 의미 입력 재생으로 절차 상태와 결과가 일치해야 한다. 물리 엔진의 부동소수점 강체 운동을 재생의 권위로 사용하지 않는다. 시각 입자 궤적은 재현성 계약에서 제외한다. 로그는 user:// 아래 저장하며 실환자 정보나 원격 전송을 포함하지 않는다.

## 검증과 완료 기준

1. Godot headless로 상태 전이·잘못된 도구·깊이·빠른 이동·새 클릭·경고·재시작·기록 재생을 검증한다. 기존 Python 테스트도 유지한다.
2. 정상 사례를 준비부터 결과까지 실제 3D 도구로 완료한다. 다른 도구를 선택하거나 공간을 벗어나면 진행하지 않는다. 전체 진행을 자동 클릭으로 대체하지 않는다.
3. 세 위험 사례에서 조작 잠금과 재개/중단 분기를 확인한다. UI와 눈·도구·모니터가 같은 상태를 표시한다.
4. 렌더 캡처로 수술실, 도구별 실루엣, 개구부, 제거 전후, IOL 전달/전개/정렬, 결과를 검수한다. 텍스트 변화만으로 조직 변화 검사를 통과시키지 않는다.
5. Windows 실행 빌드와 실행 안내, 조작표, 자산 manifest, 변경/검증 보고서를 제공한다. 헤드리스 성공과 실제 GPU 실행을 구분한다.
6. 실제 Windows에서 1080p 5분 실행의 평균/P95 프레임 시간과 오류를 기록한다. 목표 60fps는 측정 전 달성으로 표시하지 않는다. 미달 시 품질 옵션/제한을 보고한다. 4K·DPI 가독성은 별도 항목으로 기록한다.

## 구현 순서와 범위 경계

A. Godot 프로젝트·수술실·현미경·안구·UI·입력과 접촉 검증.
B. 단계별 실제 도구 메시와 전체 정상 수술 루프, 조직 반응과 IOL.
C. 위험 사례·튜토리얼·점수·기록 재생·접근성.
D. 시각/오디오 보완·Windows 빌드·GPU 측정·문서.

첫 전달물을 A의 장면만으로 완료했다고 하지 않는다. A~D를 통해 사례 선택부터 결과까지 연결된 게임을 제공한다. 사실적 외형과 의학적 정확성은 별개이며 전문가 검토 이전에 검증된 수술 훈련기로 표시하지 않는다.

## 구현자에게 위임하는 선택

세부 노드 구성, 메시 분할 수, 모델 생성 스크립트, 셰이더 구현, 게임 내부 허용 오차, 키 재지정 UI의 우선순위, 테스트 러너는 위 계약 안에서 정한다. 초기 렌더러는 Compatibility를 제안하며 실행 측정 후 필요한 경우 변경하고 근거를 남긴다. 유료 자산 구매·외부 서비스 계정·원격 배포를 전제로 하지 않는다.

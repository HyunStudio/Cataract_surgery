# 비주얼·인터랙션 디자인 기획서 v1.0 (2.5D → 3D)

## 디자인 컨셉
**Surgical microscope realism + clean clinical telemetry.**
환자의 눈이 화면의 주인공이다. 화려한 RPG 효과 대신 현실적인 광학 표현, 시야·깊이의 연속성, 정교하고 읽기 쉬운 조작 피드백을 지향한다. 연구용 실험에서는 시각적 정보의 가변성이 통제 가능해야 한다.

## 화면 레이아웃: 1920×1080 기준
- **중앙 수술 현미경 뷰** x=280~1510, y=95~880 (메인 약 64%): 원형/타원형 비네팅, 전방·홍채·수정체, 도구 오버레이, 최소 HUD.
- **왼쪽 작업 패널** x=20~260: 단계 이름, 현재 목표, 도구 트레이, 체크리스트, 도움 요청. 교육 모드는 맥락 설명, 숙련 모드는 축약.
- **오른쪽 환자/마취 패널** x=1540~1900: HR/ECG, BP, SpO2, 움직임/불안, 알람, '마취팀 호출'. 바 그래프는 보조, 상태 텍스트 필수.
- **아래 깊이 단면도 + 타임라인** y=890~1050: cornea/iris/lens/IOL 단면, 도구 Z축 위치, 단계 진행, pause. 원근 뷰와 단면 뷰는 동일한 anatomical state 참조.
- 반응형 레이아웃: 1600×900에서 패널 축소, 4K에서는 물리 픽셀을 늘리는 대신 UI scale 적용.

## 장기·도구 아트 디렉션
- **각막**: 투명 재질, 프레넬 반사, 약한 왜곡, 상태에 따른 혼탁; 투명 효과가 조작 타깃을 가리지 않아야 함.
- **홍채/동공**: 방사형 질감, 동공 크기 변화, 움직임시 자연스러운 변위.
- **수정체**: 혼탁 영역 분리, 상태에 따른 파편/투명도 변화, 낭은 별도 레이어.
- **IOL**: 접힌 형상에서 펼친 형태로 부드러운 보간; 정렬 가이드라인은 초보 모드에서만.
- **도구**: 얇고 고정밀, 커서와 실제 팁의 대응이 명확해야 함. 팁 위치·깊이 경고는 미세하지만 인지 가능.
- 혈액/조직 묘사는 의학 교육에 필요한 범위로 한정하고 과도한 고어 연출 지양.

## 2.5D 렌더링 경로
레이어: 후방 반사/수정체 → 전낭/홍채 → 전방 및 각막 → 도구 → 광학 효과 → 비네팅 → HUD. Depth buffer 유사 정렬과 정규화 Z값; object-space 조직 충돌은 게임 모델이 계산한다. UI는 Pygame surface에 표시하고 3D 출력은 별도 surface/texture로 합성한다.

## 선택적 진짜 3D 경로
독립된 Mesh/Material/Light/Camera의 scene graph 사용. Blender에서 자체 제작한 메시를 glTF 등으로 내보내고, OpenGL/ModernGL에서 렌더링. 심도는 **현미경처럼 제한된 화각**을 기본으로 하고 orbit camera는 해부학 학습 모드에서만 허용. 쉐이더: clear-cornea/refraction approximations, lens opacity, subsurface-like stylization, depth cues. 3D 도구 충돌은 렌더 메시와 분리한 단순 collider로 처리.

## 카메라와 조작
- Pan: 보조키+드래그, Zoom: 휠, Focus: 별도 슬라이더/키, Depth: 휠+보조키 또는 키 입력.
- Tool: 왼쪽 도구 선택 → 도구 팁을 현미경 공간에 매핑 → 클릭/드래그 상호작용 → 안전 피드백.
- Interactions must be **resolution-independent** and convertible between screen, camera, and anatomical coordinates.
- Assistance levels: ghost path (tutorial only), near-miss highlighting, optional hold-to-confirm for destructive simulated actions.
- 시각장애 접근성: UI 글자 14~16pt 이상 선호 옵션, 수술 뷰 전용 확대, 고대비 텍스트, 보조 단면도 확대, motion reduction, eye fatigue breaks.

## 각 단계별 특별 애니메이션
1. 프리오프: 수술실 카드/검증 체크
2. 마취: 드레이핑 전환, 협조 신호, 환자 상태 표시
3. 진입: 현미경 포커스, 도구 팁·표면 상호작용
4. 전낭: 닫힌 곡선이 생성되는 연속 애니메이션
5. Phaco: 가상 조각과 입자 흡인; 혼탁이 점진적으로 감소
6. 정리: 잔여 재질 페이드/흡인 표시
7. IOL: 접힘→삽입→펼침→중심 맞춤
8. 마무리: 전방 안정화, 미세 누출 경보, 인계
9. 결과: 눈의 투명도 before/after, 점수 항목, 이벤트 타임라인

## 예외 이벤트 디자인 원칙
합병증 경보는 주 수술 뷰 일부를 가리지 않는 주변 경고 + 오디오 + 일시정지 선택지로 제공. 심각한 이벤트에서 실수로 연속 입력이 누적되지 않도록 상태 잠금/재확인. 사용자에게 실존 환자 안전 처치법을 지시하지 않는다.

## 사운드
현미경 조작, UI 확인, 장비 주변음, 점진적 알람. 소리 OFF에서도 모든 상태는 텍스트로 전달. 심박음을 과하게 드라마틱하게 연출하지 않고 상태 기반으로 제어.

## 화면 설계 산출물 & 에셋
assets/concepts/, assets/models/, assets/materials/, assets/audio/ 위치. 메인 수술 화면, 마취/바이탈, IOL 상태, 합병증, 결과 화면의 와이어프레임 및 3D asset specification을 후속 큐에서 제작. 모델별 제작자·출처·라이선스 기록; 환자 식별 이미지 사용 금지.

## 수용 기준
각 패널의 정보 우선순위가 명확하고, 1080p/4K 확대 테스트 통과, 컬러 외 비색상 알림 제공, depth view와 operative view의 정합성, 60fps 목표에서 가독성 유지, motion reduction 설정에도 이벤트 피드백 보존.

## v1.1 보완 — 화면별 UX 계약과 디자인 QA

### 사용자 경험 목표
메인 뷰의 안전 경고 가독성을 최우선으로 유지하고 미세조작 영역에 UI가 침범하지 않게 한다. 디자인 톤은 수술 현미경 중심의 낮은 채도, 정교한 조명과 질감, 집중을 방해하지 않는 피드백. 실제 3D 질감이 생리학적 충실도나 의료적 검증을 의미하지 않는다.

### 필수 화면 다섯 종류
| 화면 | 최우선 정보 | 핵심 행동 | 완료 판정 |
|---|---|---|---|
| Case/Preop | 가상 환자·좌우안·모드 | 확인/시작 | 식별 체크 |
| Operating microscope | 수술 시야·도구 팁·단계 | 조작/시점/일시정지 | 단계 안전 게이트 |
| Anesthesia alert | 상태변화·현재 위험 | 중단/마취팀 평가 | 이유·시간 기록 |
| Complication branch | 손상 상태·안전 요구 | 인지/중단/도움 요청 | safety veto 반영 |
| Results/replay | 점수와 근거·타임라인 | 내보내기/재플레이 | 데이터 일치 |

### 카메라/입력 충돌 해소
기본 왼쪽 클릭은 도구 조작, 가운데 드래그는 pan, 휠은 zoom, Shift+휠은 깊이, 단축키는 포커스에 할당. 도구 드래그 중 카메라 팬/줌 잠금. 시야 바깥 이동 시 손상 대신 조작 중지하고 안내. 3D picking 실패 시 좌표를 임의 추정하지 않고 입력 무시와 UI 피드백. '투명 각막'의 클릭 타깃은 depth/id 버퍼로 분리한다.

### 2.5D와 3D 일관성
같은 EyeState로 두 렌더러가 동일 도구 위치와 상태 색·경고를 표시해야 한다. 해부학적 레이어와 z-index를 정의하고, 장면별 시각 회귀 캡처를 만든다. 사용자가 카메라를 회전하는 경우는 해부학 학습 뷰로 제한; 조작 과제는 표준 현미경 시야 고정.

### 화면 접근성 수용 기준
기본 텍스트 논리적 크기 16px 이상, 중요 UI는 150%/200% 확대 검토, 키보드로 중단/도움 요청 가능, 깜박임 대신 정적 경고 제공, 밝기·색 대비 옵션, 저움직임 모드에서 흔들림을 대체하는 텍스트 알림. 확대율로 인해 화면이 잘리면 패널 접기/스크롤. 시야 제한을 모사하는 *연구 조건*과 접근성 지원 기능을 명확히 분리.

### 화면 에셋 준비 우선순위
P0 와이어프레임 5화면 → P1 안구 정면/단면 제작 → P1 IOL 접힘/전개 키프레임 → P1 가상 도구 3종 → P2 각막 반사·혼탁 셰이더 → P2 조명/입자·오디오. 모델별 출처, 사용 권한, 버전, 단위/좌표축, 폴리곤 예산을 asset manifest로 관리한다.


## 2026-10-13 — 3D 인공수정체 시각화 구현·검수

- 시각화 전용 **인공수정체 광학부 + 곡선형 지지부 2개**를 자체 생성 메시로 제작했다. 의료기기 실측 치수·재료역학에 기반하지 않은 가상 모델이다.
- IOL 단계에서 접힌 표현을 표시하고, 게임 내 배치 완료 이후 CLOSE 단계에서 **시뮬레이션 시간 1.5초** 동안 점진적으로 펼치는 애니메이션을 추가했다. 일시정지하면 동작도 멈추며 수술 점수나 환자 상태를 바꾸지 않는다.
- 기존 공막 메시가 홍채·수정체를 가리던 화면 품질 문제를 발견해 공막은 깊이 판정 없는 배경으로, 홍채·수정체는 일반 깊이 판정으로 렌더링하도록 변경했다.
- CI에서 화면 중앙 200×200 픽셀만 따로 비교해 HUD 숫자 변경으로 애니메이션을 통과시킬 수 없도록 했다. Mesa 소프트웨어 OpenGL 결과와 캡처는 검수됐지만 Windows 실물 GPU, 실제 안구 광학계/삽입 역학, 임상 술기 검증은 **미완료**다.


## 2026-10-13 — 수정체낭 손상 3D 표시 검수

- 기존의 게임 안전 상태와 별도로 판정하지 않고 `Game.eye.capsule_integrity`에 따라 정상(청록색 연속 윤곽)과 손상(붉은색 끊긴 윤곽)을 GPU 3D 메시로 표시한다.
- 환자 경고 중에는 수술 조작이 차단되며 수정체낭 경고를 평가하면 안전 중단으로 연결된다. 렌더링은 상태를 변경하거나 게임 점수를 조정할 수 없다.
- OpenGL 검수에서 HUD 문구를 제외한 눈 중앙 영역만 비교해 **실제 3D 표시 차이**를 확인했다. 이상 입력, 잘못된 상태 값, 재시작·중단을 포함한 테스트를 통과했다.
- 본 표시의 간격·색·공간 위치는 교육용 추상화이며 임상적으로 검증된 낭 파열이나 실제 수술 대처법을 뜻하지 않는다. Windows 실물 GPU/4K와 전문가 검토는 별도 검수 항목이다.


## 2026-10-13 — 환자 움직임·시야 혼탁·접근성 시각화

- 3D 수술 모드에 게임 상태에 근거한 가상 안구 위치 변화와 흐림 베일을 추가했다. 환자 움직임이 발생해도 실제 수술 좌표·점수는 변경하지 않으며, 안전 경고 시에는 정지한 시각 신호와 조작 차단을 유지한다.
- **M**: 움직임 최소화(눈 영상 이동 제거), **H**: 고대비 윤곽선 표시. 텍스트 위험 경고는 항상 유지하고 번쩍이는 효과는 사용하지 않는다. 시야 혼탁 베일은 비임상적 추상화이며 실제 녹내장·백내장 시야 특성 또는 수술광학 모델로 간주하면 안 된다.
- 3D 안구 중앙 화면을 따로 비교하는 Mesa OpenGL 검수와 시뮬레이션 재현성·비정상 입력·점수 및 경고 불변성 검사를 통과했다. Windows 실물 GPU 4K 해상도의 가독성·접근성 사용자 테스트는 **미수행**이다.


## 2026-10-13 — 3D 도구 접촉 가이드 구현

- 현재 수술 단계와 가상 도구의 위치·깊이를 기준으로 **접촉 목표(녹색), 이미 수행한 구간(청색), 주변 구간(황색)**을 GPU 3D 링과 HUD 텍스트로 함께 표시한다. 색만으로 구분하지 않도록 상태 문구를 병행한다.
- 잘못된 깊이·안전 경고·일시정지·안전 중단에서는 접촉 링을 표시하지 않는다. 일시정지를 해제해도 과거의 도구 위치가 자동 복원되지 않으며 새로운 마우스 위치 검사를 거친다.
- 마우스 이동 미리보기는 수술 엔진에 액션을 보내지 않고 게임 점수·환자 상태·리플레이에 영향을 주지 않는다. 실제 처치 판단은 기존 교육용 FSM이 담당한다.
- 화면 중앙만 비교하는 Mesa OpenGL 테스트와 1,500회 무작위 유효 마우스 이동 및 비정상 입력 테스트를 통과했다. 실제 조직 충돌·힘·의학적 깊이 판정과 Windows 4K 접근성 검증은 **미완료**다.


## 2026-10-13 — IOL 접힘 형상과 3D 선택 좌표 일치

- 정적 3D 해부학 보기에서 **F** 키로 인공수정체를 펼침→접힘→중간→펼침 상태로 전환할 수 있다. 접힘에 따른 정점 위치와 정렬 오프셋을 CPU 삼각형 선택 메시에도 동일한 수식으로 반영했다.
- 화면상 안구 이동값도 역회전된 광선 원점에 반영해 마우스 선택 좌표를 보정한다. 메시 캐시는 **클릭 시 시각 상태가 바뀐 경우에만** 재생성되며, 정상 범위를 벗어난 입력·부울값·리스트·딕셔너리는 캐시에 들어가기 전에 거부한다.
- Mesa OpenGL에서는 안구 중앙 200×200 영역에서 접힘/중간/펼침 형태가 서로 다르게 렌더링되는 것을 확인했다. 같은 화면상 위치가 펼친 IOL에서는 검출되고 접힌 IOL에서는 검출되지 않는 테스트도 성공했다.
- 이 기능은 **읽기 전용 교육용 메시 확인**으로, 실제 수술 조직 충돌/삽입 역학 및 전문 의료 교육의 정확도를 입증하지 않는다. Windows 실물 GPU·4K와 실제 접근성 사용자 검수는 미완료다.

## Environment and evidence

- Windows, Python 3.12.10, Godot 4.7.2 stable official (`ed1daf0bf`).
- Actual graphics context: OpenGL 3.3.0, NVIDIA driver 566.14, NVIDIA GeForce RTX 3070 Laptop GPU, Compatibility renderer.
- Existing Python suite: **522 passed in 33.28 seconds** after adding Godot. The existing Python renderer is independent of the Godot game.
- Godot automated suites: `test_session`, `test_world`, `test_input`, `test_integration`, `test_playthrough`, all passed locally with exit 0 and no runtime errors.
- Actual GPU playthrough: preparation → continuous entry → capsule circle → separation → region-local removal/cleanup → IOL insertion/alignment → three final checks → RECOVERY, zero failures. Final exported semantic log independently replays to the same state.
- Windows release export: succeeded using the pinned official x86_64 release template. Exported `OphthoSim.exe` + `OphthoSim.pck` started with the actual NVIDIA graphics context and exited normally in a 180-frame smoke run. No editor or Python needed.

Independent reruns of the original repros and all affected suites confirmed the fixes.

## Rendering and performance

The reproducible benchmark command is:

```powershell
.tools/godot/Godot_v4.7.2-stable_win64_console.exe --path godot --resolution 1920x1080 --script res://tests/benchmark.gd
```

It samples **300 seconds** of the microscope ENTRY scene with the full eye, instrument, live monitor/UI and clock, discarding the first two seconds. It is a real graphics context, not headless/software OpenGL. It does not benchmark every active surgical effect, 4K, DPI accessibility or different hardware. Final measurement is recorded below and in `godot/reports/benchmark.json`.

| Final measurement | Observed |
|---|---|
| Resolution / duration | 1920×1080 / 300.022 seconds |
| Sampled frames after warmup | 17,873 |
| Mean frame time / mean FPS | 16.675 ms / 59.97 fps |
| P95 frame time | 18.537 ms |
| Final frame draw calls | 283 |

The machine was shared with other verification/export processes; this is an observed capped/vsync desktop run, not an isolated maximum-throughput benchmark or a guarantee for every case. No 4K/DPI or non-NVIDIA hardware acceptance is claimed.

GPU captures are generated by:

```powershell
.tools/godot/Godot_v4.7.2-stable_win64_console.exe --path godot --resolution 1600x1000 --script res://tests/test_playthrough.gd -- --capture
```

`godot/reports/01_theatre.png` through `07_results.png` were visually inspected: patient/theatre and microscope views, distinct tool geometry, visible regional tissue change, IOL transition and readable Korean result screen. Captures and local build output are intentionally ignored by Git. CI generates a separate artifact when the added workflow actually runs; no remote CI success is claimed from these local runs.

## Boundaries

This delivery is an end-to-end stylized 3D game. Tissue uses bounded regions, simplified contacts, masked/opening geometry and animation. It does not implement biomechanical tissue mechanics, clinically accurate optics, force feedback, real device settings or medically validated surgical training. Four synthetic cases are provided; VR and free walking are outside this version. The monitor is synthetic and the grade is a game score. Version 2 semantic replay reconstructs procedure state, not physical particle trajectories; Python version 1 remains separate.

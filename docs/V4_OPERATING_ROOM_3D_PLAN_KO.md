### 1.2 원칙

- **상표 없음:** 실제 제조사(Zeiss·Alcon·mindray·Sony) 로고와 이름을 쓰지 않는다. 장비는 일반 디자인이다.
- **장비 설정값 없음:** Phaco 화면은 관류·초음파·흡인·유량을 막대 길이(정성적 수준)로만 보여 준다. 숫자는 쓰지 않는다(SAFETY.md).
- **같은 상태 공유:** 모든 화면(모니터·영상·환자 눈)은 엔진 상태를 읽기만 한다. 수술실 시점을 바꿔도 점수, 판정, 리플레이는 바뀌지 않는다.
- **이미지 생성:** 사진 같은 이미지를 만드는 AI 생성 도구는 없다. 그래서 코드로 만든 3D 장면을 GPU로 렌더링해 이미지를 만든다. 사실감은 절차적 모델링 수준이다. 라이선스가 확인된 모델이 생기면 에셋 로더로 교체한다.

## 2. 설계

### 2.1 모듈

| 모듈 | 역할 |
|---|---|
| `room3d.py` | 수술실 장면 지오메트리(순수 파이썬, GL 불필요)<br>- 기본 도형(상자·원기둥·타원체·원판)과 배치 변환<br>- 기구 15종 메시<br>- 손<br>- 텍스처 화면 사각형<br>- 카메라 프리셋과 행렬 |
| `screens3d.py` | 장면 속 화면을 pygame 표면으로 그림<br>- 바이탈 모니터<br>- Phaco 콘솔<br>- 수술 영상(2D 절차적 안구 렌더러 재사용)<br>- 환자 눈 텍스처 |
| `gl_room.py` | ModernGL 렌더러<br>- 조명 셰이더: 반구 환경광, 천장광, 수술등 스포트, 금속 반사, 감마 보정<br>- 화면 텍스처 셰이더<br>- 4× MSAA 오프스크린 버퍼 |
| `or_gallery.py` | 기획 이미지와 같은 10개 패널을 PNG로 렌더링하고 한 장의 시트로 합침 |

### 2.2 좌표

- 단위는 미터, y축이 위쪽이다.
- 환자는 z축을 따라 눕는다. 머리는 z≈0, 발은 +z 쪽이다.
- 눈은 `EYE_POS`에 있고, 집도의는 머리 쪽(−z)에 앉는다.

### 2.3 게임 적용 (3D)

- `C`로 시점을 순환한다: 현미경(조작) → 수술실 전경 → 집도의 시점 → 모니터 시점.
- 수술실 시점에서는 마우스 수술 조작을 받지 않는다. 다음은 모든 시점에서 그대로다.
  - 기구 선택, 평가, 중단, 선임의 호출
  - 경보 카드
  - 게임 시간
- 써전 손에는 지금 손에 든 기구(`game.tool`)가 표시된다. 바이탈 모니터와 영상 모니터는 실제 게임 상태로 갱신된다(약 10Hz).

### 2.4 시험

- 지오메트리:
  - 모든 메시가 유효하고 방 안에 있다
  - 재질별 묶음이 렌더링 예산 안에 들어간다
  - 카메라 행렬이 유한하다
  - 집도의 카메라가 눈을 화면 중앙 부근에 비춘다
- 기구: 15종 메시 모두 유효하고, 끝이 원점에 있으며, 손에 든 기구가 게임 상태를 따른다.
- 화면:
  - 크기
  - 경보 상태에서 화면이 바뀜
  - Phaco 문구에 숫자가 없음
- 게임:
  - `C` 순환
  - 수술실 시점에서 포인터 무시
  - HUD가 수술실 모드에서 현미경 표시를 그리지 않음
- GPU: 실제 RTX 3070에서 다음을 확인한다.
  - 모든 시점이 비어 있지 않고 서로 다름
  - 갤러리 10개 패널 생성
  - 스크린샷 검수

## 3. 구현 결과 (2026-10-24)

- 설계대로 `room3d.py`, `screens3d.py`, `gl_room.py`, `or_gallery.py`를 구현하고 3D 게임에 `C` 시점 전환을 넣었다.
- 설계와 다른 점: **현미경 접안 시야**(`scope`)를 추가했다. 현미경 대물렌즈 아래에서 눈을 내려다보는 3D 카메라다. 텍스처를 입힌 실제 안구 화면, 3D 기구, 손이 함께 보인다. 기획 이미지의 2번 패널은 이 시야로 만들었다.
- 1080p에서 측정한 수술실 시점 프레임 시간: 평균 9.5ms, p95 17.8ms(화면 갱신 포함, RTX 3070).
- 시험: 테스트 865개 통과. GPU에서 갤러리 10개 패널 생성, 실제 게임 루프로 다섯 시점 확인.
